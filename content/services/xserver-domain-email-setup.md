# 日本 Xserver 域名申请与企业邮箱搭建指南

如果你已经准备使用日本 Xserver 搭建网站或企业邮箱，建议先把域名、DNS、邮件账号和发信认证按顺序处理。邮箱最常见的问题不是“账号创建失败”，而是域名还没有正确指向、客户端端口填错、SPF/DKIM/DMARC 没有配置，结果邮件能发却进垃圾箱，或者能收却发不出去。

本文以 Xserver 的标准控制台流程为主，适合搭建类似 `info@example.jp`、`support@example.jp` 的域名邮箱。示例中的 `example.jp` 是无效占位符，实际操作时请替换成自己的域名。

> 本文参考 Xserver 当前公开的官方手册整理。控制台名称、活动优惠和套餐限制可能变化；最终应以登录后看到的 XServer 账户和服务器面板为准。

## 先确认你要使用哪一种 Xserver 服务

Xserver 的产品线不止一种，操作入口和邮件能力不要混在一起：

- **Xserver Rental Server**：域名、网站和域名邮箱通常在服务器面板中统一管理，适合企业站、个人站和常规邮箱。
- **XServer VPS**：更适合自定义部署应用。域名可以在 XServer 侧申请或管理，但邮箱服务是否由 Xserver 提供，要看具体产品和部署方案，不能直接照搬 Rental Server 的邮件面板步骤。
- **外部邮箱服务**：如果邮箱由 Google Workspace、Microsoft 365 或其他邮件服务提供，Xserver 只负责域名和 DNS。此时 MX、SPF、DKIM、DMARC 应以邮箱服务商的记录为准。

本文主要覆盖第一种情况，并在 DNS 部分说明使用外部邮箱时需要怎么分流。

## 完整流程概览

建议按照下面的顺序执行：

1. 在 XServer 账户中申请或准备域名；
2. 确认域名的 NS 或 DNS 托管位置；
3. 在服务器面板中添加域名；
4. 等待域名设置生效；
5. 创建第一个邮箱账号；
6. 用 Web 邮箱确认收发；
7. 再配置手机、电脑或 Gmail 的 IMAP/SMTP；
8. 开启并检查 SPF、DKIM 和 DMARC；
9. 做一次外部收信、外部发信和垃圾邮件测试；
10. 保存恢复信息，但不要把密码写进 Git 或公开 Wiki。

## 一、申请或准备域名

### 1. 选择域名

先确定主域名和邮箱用途。建议把品牌主域名和内部测试域名分开考虑：

| 用途 | 示例 | 建议 |
|---|---|---|
| 对外网站 | `example.jp` | 作为主域名 |
| 对外邮箱 | `info@example.jp` | 与网站主域名保持一致 |
| 客服邮箱 | `support@example.jp` | 由多人或工单系统管理 |
| 系统通知 | `notify@example.jp` | 不建议作为人工回复地址 |
| 测试环境 | `staging.example.jp` | 不要误用生产邮箱 |

域名要尽量短、容易拼写，并提前确认续费责任人。Xserver 的独自域名入口和当前可申请的后缀，以官方域名页面为准。[1]

### 2. 在 XServer 账户中申请

登录 XServer 账户后，从服务申请或域名相关入口开始申请。常见流程是：

1. 选择域名服务或域名新规申请；
2. 输入想要的域名并检查是否可注册；
3. 选择后缀和计费周期；
4. 确认注册人、管理联系人和付款信息；
5. 完成申请后，在账户中确认域名状态和有效期。

域名申请成功不代表已经能用于网站或邮箱。后面还必须把它添加到具体服务器，并确认 DNS/NS 已经指向正确的位置。

### 3. 如果域名在其他注册商

不一定要把域名转移到 Xserver。可以保留原注册商，只把 DNS 记录指向 Xserver；也可以把域名的 NS 改到 Xserver 管理。

这两种方案的区别很重要：

- **由 Xserver 管理 DNS**：邮件、网站和 SSL 的入口比较集中，适合希望少维护一个控制台的情况；
- **由外部 DNS 管理**：更灵活，适合已经使用 Cloudflare 或企业 DNS 的情况，但所有 MX、SPF、DKIM、DMARC 记录都要在外部 DNS 修改。

不要同时在两个地方维护同一组 DNS 记录。先确定“谁是权威 DNS”，再进行下一步。

## 二、把域名添加到 Xserver

取得域名后，需要在服务器面板中添加域名。官方手册的路径是“服务器面板 → ドメイン設定 → ドメインを追加”。添加域名时，Xserver 会同时尝试添加免费独自 SSL。[2]

操作步骤：

1. 登录服务器面板；
2. 打开“域名设置”；
3. 选择“添加域名”；
4. 输入完整域名，例如 `example.jp`；
5. 确认拼写，提交添加；
6. 检查域名列表中的状态。

官方说明指出，域名设置的反映可能需要数小时，最长可能达到 24 小时。[2] 在此期间看到“反映待ち”或访问不稳定，不要反复删除和重新添加域名。

添加完成后，Xserver 会为该域名创建对应目录。网站文件通常放在该域名目录下的 `public_html`，邮件数据则使用 Xserver 的邮件系统管理，不要直接修改邮件目录中的系统文件。[2]

### 常见失败：域名已经被其他 Xserver 账号使用

如果提示该域名已经设置在其他 Xserver 服务器上，不能简单地在新服务器重复添加。同一个域名不能同时作为多个 Xserver 服务器的同类设置。[2]

迁移时应按下面顺序处理：

1. 先备份旧网站和旧邮箱需要保留的数据；
2. 确认旧服务器上的域名设置确实可以删除；
3. 删除旧设置后，再在新服务器添加；
4. 等 DNS 和服务器设置完成后，做网站与邮件测试。

不要为了绕过错误直接删除旧域名设置。官方手册提醒，删除旧设置前如果没有先下载网站数据，可能造成数据丢失。[2]

## 三、确认域名和 DNS 指向

### 1. 使用 Xserver 的 DNS/NS

如果域名也由 Xserver 管理，通常可以按照 Xserver 的域名设置和名称服务器手册完成 NS 配置。[3] 修改 NS 后，不同 DNS 缓存的更新时间可能不同，因此要用实际查询结果确认，而不是只看控制台提示。

### 2. 使用外部 DNS

如果域名的权威 DNS 在其他服务商，网站和邮箱相关记录也必须在那个服务商处维护。Xserver 官方 DNS 编辑手册说明了通过 DNS 记录管理入口添加和修改记录的方式。[4]

外部 DNS 场景至少要核对：

- `A` 或 `AAAA`：网站访问地址；
- `MX`：邮件接收服务器；
- `TXT`：SPF、DMARC 等文本记录；
- DKIM 专用记录：以 Xserver 面板显示的主机名和值为准；
- 不要残留旧邮箱服务的 MX 记录。

MX 记录存在多个服务商时，邮件可能被分流到错误的位置。迁移邮箱前要先列出现有 MX，再决定保留或删除哪些记录。

## 四、创建第一个邮箱账号

域名添加完成后，进入“服务器面板 → メールアカウント設定”。官方流程要求先完成域名设置，然后在邮件账号设置中选择“添加邮件账号”。[5]

建议先创建一个人工使用的地址，例如：

- `info@example.jp`：一般对外联系；
- `support@example.jp`：客服；
- `admin@example.jp`：管理用途，尽量不要公开；
- `noreply@example.jp`：系统发信，不接收人工回复。

创建账号时填写：

- 邮箱账号名；
- 强密码；
- 邮箱容量；
- 备注。

不要让多个员工共用同一个密码。多人使用时，应分别创建账号，或者使用转发、别名和共享邮箱方案。Xserver 官方手册还提示，试用期间可能无法添加邮箱账号；如果按钮不可用，先确认账户是否已正式开通。[5]

## 五、先用 Web 邮箱做验收

客户端配置之前，先使用 Xserver 提供的 Web 邮箱完成基础测试。这样可以把“服务器端账号问题”和“手机/电脑客户端配置问题”分开。

建议做三次测试：

1. 从 Web 邮箱向外部邮箱发送一封测试邮件；
2. 从外部邮箱回复到 `info@example.jp`；
3. 在 Web 邮箱中确认回复正常到达，并检查邮件头中的认证结果。

Web 邮箱适合临时访问和故障排查，但不应把它当成备份。重要邮件仍应使用合适的客户端、归档策略和备份方案。[11]

## 六、配置手机、电脑和 Gmail

Xserver 官方邮件客户端手册给出的核心参数如下。[6]

| 项目 | 推荐值 |
|---|---|
| POP/IMAP 服务器 | Xserver 设置完成邮件中的“邮件服务器”主机名，例如 `sv***.xserver.jp` |
| SMTP 服务器 | 与 POP/IMAP 使用同一个邮件服务器主机名 |
| 用户名 | 完整邮箱地址，例如 `info@example.jp` |
| 密码 | 创建邮箱账号时设置的密码 |
| IMAP + STARTTLS | 143 |
| IMAP + SSL/TLS | 993 |
| POP + STARTTLS | 110 |
| POP + SSL/TLS | 995 |
| SMTP + STARTTLS | 587 |
| SMTP + SSL/TLS | 465 |

### 为什么优先使用 IMAP

如果同一个邮箱要在手机、电脑和 Web 邮箱之间同步，优先选择 IMAP。Xserver 官方说明也建议不要同时混用 POP 和 IMAP，因为可能出现邮件状态、已读标记或删除状态不一致。[6]

推荐组合：

- 接收：IMAP + SSL/TLS，端口 993；
- 发送：SMTP + SSL/TLS，端口 465；
- 用户名：完整邮箱地址；
- SMTP：开启“需要身份验证”。

如果当前网络对 465 有限制，可以尝试 SMTP + STARTTLS 的 587。不要为了“能发出去”而关闭 TLS 或身份验证。

### SMTP-AUTH 必须开启

Xserver 推荐使用 SMTP 认证，也就是 SMTP-AUTH。[6] 客户端中可能叫“需要身份验证”“密码认证”或“传出服务器需要验证”。发送服务器的用户名和密码应与邮箱账号一致。

如果可以收信但不能发信，优先检查：

- SMTP 服务器主机名是否填成了 Xserver 邮件服务器；
- 端口是否使用 465 或 587；
- 是否开启 SMTP 认证；
- 用户名是否填写完整邮箱地址，而不是只有 `info`；
- 是否触发了 SMTP 安全限制。

## 七、开启邮件认证：SPF、DKIM、DMARC

域名邮箱能收发，不代表发信信誉已经做好。SPF、DKIM 和 DMARC 解决的问题不同：

| 机制 | 解决什么问题 | Xserver 操作 |
|---|---|---|
| SPF | 哪些服务器可以代表域名发信 | 面板中的 SPF 设置 |
| DKIM | 邮件是否由授权系统签名、内容是否被篡改 | 面板中的 DKIM 设置 |
| DMARC | SPF/DKIM 失败后，接收方如何处理 | 面板中的 DMARC 设置 |

### SPF

Xserver 手册说明，添加独自域名时会自动追加标准 SPF 记录，也可以在服务器面板中查看和调整。[9]

如果只有 Xserver 负责发信，先使用标准设置。不要随意新增多个 SPF TXT 记录；同一个域名应合并成一条 SPF 记录。需要同时允许 Gmail 或其他外部发信服务时，按官方手册增加对应授权，并重新检查 DNS 查询结果。[9]

### DKIM

DKIM 用私钥签署发出的邮件，收件方通过 DNS 中的公钥验证。Xserver 的操作路径是“服务器面板 → DKIM 设置”，通常将目标域名从 OFF 切换为 ON 即可。[8]

如果 DNS 由其他服务商管理，Xserver 面板会显示需要添加的 DKIM DNS 记录。把这条记录复制到权威 DNS 后，再等待解析生效。[8] 不要自己猜 selector、主机名或 TXT 值，直接使用面板显示的内容。

### DMARC

DMARC 用来规定 SPF 或 DKIM 失败时的处理策略，并可接收认证报告。[10]

推荐分阶段上线：

1. 初期使用较宽松的策略，例如“什么都不做”；
2. 开启报告，把报告地址设为不会介意公开在 DNS 中的邮箱；
3. 观察所有合法发信源是否通过 SPF/DKIM；
4. 确认无误后，再逐步收紧为“标记为垃圾邮件”；
5. 最后才考虑拒收。

不要在还没有盘点所有发信系统之前直接使用拒收策略。网站表单、CRM、营销工具、GitHub 通知和人工邮箱可能来自不同的发信服务器，漏配任何一个都可能导致正常邮件被拒收。

## 八、邮件安全设置

Xserver 提供 SMTP 认证安全设置，可以按域名限制特定 IP，或限制来自国外 IP 的不正当发信。[7]

建议按使用方式选择：

- 主要通过 Web 邮箱和日本境内客户端使用：保持国外访问限制开启；
- 有人在海外旅行或通过海外云服务器发信：先确认真实发信路径，再调整限制；
- 使用 Cloudflare、海外 VPS 或其他代理：注意代理出口 IP 可能被判断为国外；
- 使用固定办公网络：可以评估 IP 白名单，但必须准备移动网络和故障恢复方案。

IP 限制不是万能安全措施。邮箱密码仍需使用随机长密码，客户端应启用 TLS，管理账号不要公开，离职或不再使用的账号要及时停用。

## 九、邮件表单与垃圾邮件风险

如果网站有“联系我们”表单，不要把用户输入直接作为邮件的 `From` 地址。正确做法是：

- `From` 使用自己域名下的固定地址；
- 用户邮箱放在 `Reply-To`；
- 对表单加入验证码、频率限制和长度限制；
- 对邮件头、换行符和附件类型做校验；
- 限制单个 IP 的提交次数；
- 记录失败次数，但不要记录完整密码或敏感内容。

Xserver 官方也单独提供了邮件表单被恶意利用的说明。[12] 表单能正常发送，不代表它已经具备抗滥用能力；上线前应测试空提交、超长输入、重复提交和伪造邮箱地址。

## 十、验收清单

### 域名和 DNS

- [ ] 域名注册状态正常，续费日期已记录；
- [ ] 权威 NS 已确认；
- [ ] 域名已添加到 Xserver 服务器面板；
- [ ] 网站 A/AAAA 记录指向正确；
- [ ] 旧邮箱服务的 MX 记录已清理或明确保留；
- [ ] SSL 已签发并能正常访问。

### 邮箱账号

- [ ] `info@example.jp` 已创建；
- [ ] 使用唯一强密码；
- [ ] Web 邮箱可以登录；
- [ ] 外发邮件可以到达外部邮箱；
- [ ] 外部回复可以正常收到；
- [ ] IMAP/SMTP 客户端配置完成。

### 发信认证

- [ ] SPF 只有一条有效记录；
- [ ] DKIM 已开启，外部邮件头能看到签名结果；
- [ ] DMARC 先以观察模式运行；
- [ ] 已确认网站表单和其他系统的合法发信源；
- [ ] 没有把密码、Token 或私钥写进文章、脚本和 Git。

## 常见问题排查顺序

### 能收信，不能发信

先检查 SMTP 主机名、465/587 端口、SMTP-AUTH 和完整邮箱用户名，再查看是否触发 SMTP 安全限制。不要先修改 MX 记录，因为 MX 主要决定收信路径。

### 能发信，但 Gmail 或 Outlook 收不到

先检查收件方垃圾邮件，再检查 SPF、DKIM、DMARC 和发信 IP 的信誉。确认邮件头中的认证结果，不要只看 Web 邮箱显示“发送成功”。

### 修改 DNS 后没有立即生效

检查修改的是权威 DNS，而不是另一个不生效的控制台。然后等待缓存 TTL 和 Xserver 官方说明的反映时间。使用多个外部 DNS 查询点交叉确认。

### 网站正常，邮箱突然不能收

优先检查 MX 记录是否被 CDN、网站迁移或其他 DNS 修改覆盖。网站的 A 记录正确，并不代表邮件的 MX 记录也正确。

## 小结

Xserver 域名邮箱的正确搭建顺序是：先申请或准备域名，再确认权威 DNS，添加域名到服务器面板，创建邮箱账号，用 Web 邮箱做基础验收，然后配置 IMAP/SMTP，最后补齐 SPF、DKIM 和 DMARC。

把“域名能访问”和“邮件可信可达”分开验收，很多问题会更容易定位。尤其是迁移或使用外部 DNS 时，不要凭感觉复制一条 MX 或 TXT 记录；以 Xserver 面板显示的服务器信息和官方手册为准。
