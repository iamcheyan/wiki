# Hermes Agent 使用指南

## 它能做什么

Hermes Agent 的核心能力包括：

- **问答与研究**：搜索网页、提取页面内容、整理资料并给出引用来源。
- **文件操作**：读取、搜索、创建和修改文本、代码、配置及文档文件。
- **系统操作**：运行命令、检查系统状态、启动或管理后台进程。
- **代码开发**：检查代码库、编写功能、运行测试、查看 Git diff，并在完成后验证实际结果。
- **多代理协作**：把相互独立的子任务交给 `delegate_task`，由隔离的子代理并行处理。
- **自动化**：通过定时任务、监控脚本和事件触发器执行周期性工作。
- **技能与记忆**：技能保存可复用的操作流程；持久记忆保存少量高价值的长期事实和偏好；完整资料应保存到知识库或项目文件。
- **多种交互界面**：可通过终端、TUI、桌面应用、Dashboard 以及已配置的消息平台使用。

## 如何提出任务

越具体越容易得到可验证的结果。建议说明：

1. **目标**：最终要得到什么。
2. **范围**：允许修改哪些目录或文件。
3. **限制**：是否禁止重启服务、删除数据、联网、提交或推送。
4. **验收标准**：需要运行哪些测试、检查哪些页面或生成什么文件。
5. **交付方式**：回复摘要、写入知识库、提交 Git，或生成附件。

例如：

> 检查这个项目的登录问题，只修改后端目录；先找出根因，再修复并运行测试，不要重启生产服务。

## 结果验收原则

Agent 不应只给出计划或看起来合理的描述。涉及构建、运行、修改或发布时，应当：

- 实际执行对应操作；
- 检查命令、测试或构建的真实输出；
- 查看修改后的 diff 或生成文件；
- 对外部副作用验证返回的 URL、ID、文件路径或远端状态；
- 如果受到权限、网络或工具故障阻塞，明确报告阻塞原因，不编造结果。

## 常用能力的边界

- **工具调用**用于实际查询和操作，不应被文字说明替代。
- **子代理**适合独立、耗时或需要专门分析的任务；涉及用户选择的决策不能交给无法询问用户的子代理。
- **定时任务**必须写成自包含说明，因为执行时没有当前聊天上下文。
- **公开知识库**适合长期、可复用的脱敏文档，不适合保存秘密或私人聊天记录。

## 配置原则

Hermes 的一般约定是：

- 配置写入配置文件，密钥和其他凭据只放在受保护的环境变量文件中；
- 不在公开仓库、Markdown、提交信息或日志中写入秘密；
- 修改 Hermes 自身配置时优先使用官方 CLI 或配置命令，并先读取官方文档；
- 不把某个配置文件的当前内容当成通用事实，遇到版本差异时以官方文档和实际命令输出为准。
